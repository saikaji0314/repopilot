# 第 2 期实现顺序

> 进度：工具主体和接入冒烟已完成，题集共 10 题，Flask 本体两题已本地预检。下面保留逐步实现教学顺序；当前下一步为片段排序/截断收尾及 A/B 开关，见 [较大仓库与收尾路线](./LARGER_REPO.md)。

以下接口是建议，不代表已经存在。每步自己写伪代码，先写少量行为测试，再实现、解释与复核。

## 步骤 1：明确现有搜索契约

涉及现有 `repopilot/legacy/tools/search.py`、`base.py`、`arguments.py` 和 `tests/tools/test_search.py`。保持函数签名与 ToolResult 外壳。

约定：query 是区分大小写的非空字面子串，`.*` 不表示正则；path 指目录；不存在返回 `path_not_found`，传文件返回 `not_a_directory`，不能默默当零命中。file_pattern 仍用现有白名单简单扩展名模式，输出相对路径和从 1 开始的行号。

完整搜索无匹配才返回 `ok=True, matches=[], truncated=False`；截断不能推出仓库中不存在目标。直接访问忽略目录应拒绝，逐候选文件验证最终解析路径，越界候选跳过且不读取内容。

先补四个小测试：字面 `.*`、大小写区别、不存在目录、传入文件。保留现有行号/空 query/白名单/符号链接测试，再补直接访问忽略目录的测试。只修对应实现和工具描述，不修改 Loop。

在项目 .venv 执行 `python -m pytest tests/tools/test_search.py -q`。理解题：空匹配和工具错误为什么不同？为什么验证入口路径不足以保证每个候选文件安全？

## 步骤 2：模型与 AST 索引

建议 Symbol 字段：path、qualified_name、kind（function/class/async_function）、start_line、end_line。RepositoryIndex 包含 symbols、files、warnings、truncated。路径相对工作区，行号包含首尾，从 1 开始；有装饰器时起点取最早装饰器行。

建议 `build_index(workspace: Path) -> RepositoryIndex`。只 ast.parse，不 import 仓库代码；嵌套名称如 Service.update，同名符号以文件和位置区分。稳定排序，限制文件数量与单文件大小；语法错误、跳过、截断显式记录，不静默假装完整。

五类小测试：函数/类方法行号；异步与装饰器；不同文件同名；坏文件不阻止好文件；忽略目录/越界文件不进入索引。用 tmp_path 写几行测试源码，不需要模型或大仓库。

## 步骤 3：检索与排序

建议 `search_index(index, query, limit) -> list[SearchHit]`，命中包含 path、start_line、end_line、reason。先精确符号名，再符号子串/路径；同优先级按路径、行号稳定排序。查询使用代码标识符/路径线索，别把简单匹配称为自然语言理解。

逐行关键词继续用已有工具；未命中允许空，不臆造符号。测精确优先、稳定顺序、条数限制、无命中四项，不先做复杂权重。

## 步骤 4：片段与预算

按命中读取带来源/行号的片段，同文件重叠范围合并，按排序装入总字符预算。明确截断和后续可读取范围。字符不是 Token，不能声称精确控制计费。

首版只对本次候选片段去重，不删除历史 tool 消息或破坏 call ID 配对。测试重叠合并、跨文件不误合并、超预算截断、空结果、超长单行仍受限。

## 步骤 5：工具接入

新增一个受控符号检索工具，通过已有 ToolRegistry 注册，返回 ToolResult。每个缺陷任务的准备工作区建立自己的索引，不误用干净基线或别题结果。

先用 Fake 模型测“检索 → 读片段 → 回答”。支持关闭新工具供对照；保存实际工具 schema、模型配置、任务/提示词版本。不同时换 SDK、重构 Loop、改格式恢复。

## 步骤 6：扩样与评测

步骤 5 的接入检查已增加：

- `tests/agent/test_search_symbols_integration.py`：Fake 模型配合真实索引、工具注册表与 Loop，检查两次检索、下一轮消息和 Trace。运行 `python -m pytest tests/agent/test_search_symbols_integration.py -q`，不联网。
- `python -m scripts.smoke_search_symbols`：会调用真实百炼接口并产生费用，仅运行 login 一次。附加用户指令明确要求先使用新工具，不修改正式任务/系统提示词；结果单独保存在 `evals/runs/smoke/`，包含工具 schema 和冒烟标记，不计入自主检索评测。请勿把此命令加入默认单元测试。


先选可信较大样例并检查依赖/执行边界，再设计至少两个跨文件任务。候选方向如“调用方与被调用方参数语义不一致”“配置覆盖跨模块失效”；这些只是方向，不是已创建的任务或 Oracle。

每题先定输入、预检、缺陷现象、关键证据位置和 Oracle。旧/新方案在同一完整 8 题集固定次数运行，不挑最好结果；先审实际模型观察，再审最终结论。

ordering 收尾另做第二个实验：提示剩余预算，或研究预算内禁工具收尾。先定义是否预留模型步骤，不能耗尽后绕过限制强行再调用。收尾收益不与检索收益混报。
