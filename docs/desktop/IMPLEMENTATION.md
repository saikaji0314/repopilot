# 桌面执行详情：实现与验证

2026-10-30。执行详情视觉已确认，Windows x64 安装程序已构建并通过本机隔离安装验收，作为 v0.2.0rc1 桌面预发行；完整桌面产品尚未完成。[需求基线](REQUIREMENTS.md)继续约束后续开发，不以设计预览代替真实功能。

## 当前行为

- 执行页沿用确认稿，默认 216px 应用导航、224px Agent 区、单控制台与下划线标签。两处分栏可拖动、键盘调整、双击复位及独立折叠；导航支持 Ctrl+B，Ctrl+K 会恢复隐藏的导航并聚焦搜索。布局通过受限 IPC 存于本机，随机服务端口变化后仍保留。宽度按窗口可用空间收窄，避免挤占控制台。
- 默认读取真实 SQLite 运行记录及对应脱敏事件。没有运行时显示空状态；示例需显式选择设计预览 URL，且不发出真实操作。
- 工具动作可展开、查看读取范围与参数、搜索日志、筛选失败、复制路径、下载当前 Agent 日志；改动、独立检查与审核单独查看。
- 新事件带动作关联 ID，工具结果和命令块按 ID 配对；并行实现事件增加 Agent 和子任务身份。旧记录只有一个匹配中的动作时才配对，存在歧义不猜测；运行结束后仍无对应结果的动作标为结果未关联。
- 本机登记命令在结束前按完整行提供有界输出，最终结果仍保留原首尾截断和退出码。独立验证也使用该通道。Docker 仍在命令结束时提供结果，尚无容器实时输出。
- 事件接口每秒检查持久化追加，使用文件字节位置作为游标；未写完的行不消费。重连从头补读并按持久化事件 ID 替换／去重，文件缩短触发重置。事件文件须沿用现有只追加协议，不承诺任意外部改写后仍能无损增量读取。
- 服务中断或 10 秒没有更新时展示状态待核对，保留最后记录并禁用人工副作用入口。成功轮询列表不会覆盖失联状态。
- 发布决定调用现有 `workflow.decide`，核对快照 revision、完整候选 SHA、审核依据和实际工作区。UI 仅记录本地批准／拒绝，不创建 PR、不代替原生 Approve。
- 澄清入口携带人工请求 ID 和版本，调用现有 `human.answer`；当前只保存答复，之后通过 CLI `resume` 显式恢复。普通评论不走此接口。
- 暂停是合作式阶段暂停：收到后等待当前阶段结束及现场检查点完成，不中断在途工具；界面明确显示该边界。控制请求与业务检查点分开存储，不冒充已经暂停。
- 设置提供 App 创建／安装／权限／数字 ID／PEM 导入引导和模型 Key／预算设置；环境与桌面来源显式选择。桌面凭证以 Windows 当前用户 DPAPI 加密、版本校验和原子替换保存，不更改 `.env` 或已有账本。保存后只返回是否已配置，校验错误不回显输入。私钥在内存中供已有 App 认证使用，不解密落到临时文件。
- GitHub 连接检查读取 App 身份与指定仓库，模型检查仅校验格式，均不发评论或模型推理。当前桌面模型设置尚未接入启动 worker 的入口；现有 CLI 仍读取原环境配置，不声称保存即已改变执行模型。
- Issue 讨论接上评论读取与显式发送，发送前显示机器人／本人身份；本人令牌须匹配登记负责人。普通评论以专用前缀排除出既有正式答复路由。跨进程投递锁和持久化记录防止重复；超时先核对完整正文与作者，未知结果不自动重发。草稿投递编号在重载后保留；评论正文以文本呈现，不运行远端 HTML。
- 运行目录可通过原生目录选择器更换，启动新读取服务就绪后载入，失败恢复原连接；只停止自己的旧读取服务，不迁移数据或停止 CLI worker。连接设置按运行目录独立保存。

## 结构与边界

Electron 管理窗口、托盘和一个 Python 读取服务；执行 worker 仍由已有 CLI／调度器负责。本轮未引入新的模型执行进程。关闭窗口隐藏到托盘；退出桌面端只结束自己的读取服务，不强杀已有 CLI 任务。已实测关闭隐藏与重开同一运行；尚未做真实长任务期间的完整托盘验收。

服务只绑定随机的 `127.0.0.1` 端口。主进程生成单次会话 token，经环境传给 Python、经校验后的 preload IPC 传给同源主窗口；token 不出现在 URL 或服务 stdout。API 同时检查 Host、Origin 和 Bearer 会话。renderer 使用 sandbox、context isolation，关闭 Node integration、新窗口与任意导航。外部链接仅允许无凭证的 HTTPS。

只读投影白名单返回工具事件和产品证据，不返回模型会话、settings、环境变量或原始数据库正文；嵌套结果先解析再脱敏，显示前再次清理常见凭证形式。产物路径固定在指定运行目录内。空目录的查询不创建数据库。实际业务操作继续调用原有门禁，不由前端改数据库。

## 接口

除健康检查和静态资源外，下表均要求当前会话的 `Authorization: Bearer …`。

| 方法与路径 | 内容 |
| --- | --- |
| `GET /health` | 服务协议版本和就绪状态，不返回业务数据 |
| `GET /api/runs` | 最近运行摘要与已有队列，只读 |
| `GET /api/runs/{id}` | 执行详情、证据和可用操作 |
| `GET /api/runs/{id}/events?cursor=N` | SSE 快照、允许的增量事件和下一游标 |
| `POST /api/runs/{id}/pause` | 带 revision 的阶段安全点暂停请求 |
| `POST /api/runs/{id}/decision` | revision、完整 commit、approved 和 reason |
| `POST /api/runs/{id}/answer` | revision、request_id、version 和正式答复 reason |
| `GET /api/settings` | 公开配置字段、版本及凭证是否存在，不返回凭证原文 |
| `POST /api/settings` | 版本绑定配置保存、留空保留／显式清除凭证 |
| `POST /api/settings/check-github` | 保存配置的只读身份与仓库检查，不验证写权限 |
| `POST /api/settings/check-model` | 配置格式检查，不发推理请求 |
| `GET /api/runs/{id}/comments` | 从持久化 Issue 身份解析目标并读取评论 |
| `POST /api/runs/{id}/comments` | body、sender、client_id；显式发送或核对同一草稿 |

状态冲突／过期返回 409，缺少运行返回 404，缺少会话返回 401。配置校验返回不含输入原文的字段路径；平台错误返回脱敏错误码。没有通用命令执行或任意文件读取接口，GitHub 写入只限持久化运行所关联 Issue 的显式普通评论。

## 验证证据

- v0.2.0rc1 发行回归共收集 836 项：分段完成 824 passed／12 skipped。首次全量运行在旧工单夹具处得到 767 passed／11 skipped／1 failed；相同代码将临时目录从本机构建盘改到 C 盘后，旧夹具 4 项通过，随后剩余 58 项得到 57 passed／1 skipped。不是一次全绿的单次运行；初次失败保留，未更改旧夹具代码或隐藏失败。
- Windows `.exe` 安装程序包含 Electron 与冻结 Python 服务。实际安装版在移除 Python／Node.js PATH 后通过原生设置加密／进程重启／布局恢复／目录切换，以及托盘／401／实际 diff／隔离固定候选批准测试。安装资源 1590 个文件经检查，没有本地运行数据、构建来源 direct_url 或本机凭证匹配；校验值随发行提供。尚未在独立干净 Windows 虚拟机验证。

- 分栏／连接／评论增量：58 项 Python 专项通过，含真实 Windows DPAPI 保存／恢复、配置不回显／留空保留／显式清除、版本冲突、真实 RSA 与合成 GitHub HTTP、评论身份与重复发送／丢响应／伪造标记／跨进程锁，以及既有正式答复回归。采用短临时路径避免 Windows 长路径影响夹具，不代表真实模型效果。
- 当前 14 项浏览器用例通过：包含下述原执行页与真实服务验证，新增两处分栏拖动／键盘／折叠／重载记忆／Ctrl+K、设置向导与焦点约束、纯文本评论及同一草稿在重载后继续核对。UI 的 GitHub 响应为模拟数据。
- 新增原生设置 smoke 通过：隔离用户配置和运行目录，导入合成 RSA PEM／模型 Key，经真实 API 和 Windows DPAPI 保存；关闭进程再开后配置和布局恢复、Key 不回显、运行目录切换并持久化成功。未调用 GitHub 或模型。
- 沿用已有本机环境配置，真实只读核对 GitHub App 身份与当前仓库成功；该仓库没有可用于本轮读取的 Issue，未进行真实评论读取／发送验收。新用户首次注册／安装全流程及真实写入仍待验证。

- 构建与 TypeScript 检查通过；依赖与字体均本地打包，24 个 Figma SVG 文件非空，未留下临时素材 URL。
- 浏览器 10 项测试通过：三种状态、两种宽度、图标几何、字体断言、日志搜索／失败筛选／标签页、批准说明与预览隔离、真实模式空状态；截图目视核对后修正了字体继承和初次滚动。

- 72 项受影响 Python 用例通过、1 项链接用例按 Windows 权限条件跳过，覆盖新接口、实际子进程输出、真实本地 Git 的固定候选审批、阶段暂停、仓库工具、恢复、并行实现和审核。使用确定性模型，不计费；不是全量回归。
- 原生 Electron smoke 已通过：renderer 无 Node 对象、无 token 查询被拒、preload 会话可用、关闭按钮隐藏到托盘、重开同一运行、实际 diff 可见、隔离候选的本地批准成功并回读确认。使用独立的真实 Git／确定性模型夹具，未访问或批准原业务运行。
- 保留启动失败记录：官方 Electron 45.1.0 校验和匹配，但它在原开发目录中运行 `--version` 即以 `0x80000003` 退出。将同一份压缩包解到另一处已授权目录后，版本探针和原生 smoke 均成功，证据支持“与运行时放置目录有关”，尚未确认更细根因。官方存在类似的 [Windows 启动问题](https://github.com/electron/electron/issues/54614) 和 [安装目录权限诊断](https://github.com/electron/electron/pull/54484)。没有关闭 sandbox；针对原生成 runtime 目录的临时读取权限探针无效且已还原。本机另存忽略的运行时目录配置，公共启动器只支持显式的本地路径覆盖，不自动扩大目录权限。
