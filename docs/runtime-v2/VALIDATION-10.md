# 增量10：单次运行的静态展示报告

验证日期：2026-10-17。范围：把一次已完成运行的本地证据渲染成**单文件、可离线打开**的 HTML 报告。本轮不做实时控制台，不做录屏，不做网页审批。

## 目标与边界

目标是让观众不读 JSON 也能看清一条工单交付的证据链：需求来源、关键指标、阶段时间线、实现报告、候选改动与差异、独立复核、审核与返工、人工决定、远端产物。

明确不做：

- 不做多运行列表、不做实时刷新、不做网页审批或任何写操作；
- 不展示原始模型会话、完整 prompt、`input.json` 的设置全文、预算账本；
- 不把「计划中」的能力画成已有事件；
- 不改变任何运行结果，报告只读已落盘证据。

## 实现

新增 `repopilot/presentation/report.py`，从 `JobStore` 的状态与 run 目录读取，生成自包含 HTML（内联样式、不含脚本、不引用外部资源）。新增 CLI 子命令：

```powershell
.\.venv\Scripts\repopilot.exe report <run_id> --html <路径>
```

默认写到 `<输出目录>/reports/<run_id>.html`。数据来源：

| 展示项 | 来源 |
| --- | --- |
| 需求来源、关键指标、人工决定、远端产物 | `jobs.sqlite3` 的 job 状态 |
| 候选改动与差异 | 该 run 的 `changes.json` |
| 独立复核 | 状态里的 `verified`（编排层复核结果） |
| 审核与返工 | 状态里的 `history` 与 `review_report` |
| 阶段时间线 | 该 run 的 `events.jsonl`，按时间顺序编号审核轮次与返工次数 |

脱敏与转义：

- 本机绝对路径（项目根与用户 home）替换为 `<本机路径>`；
- `API_KEY`／`DS_API_KEY`／`GITHUB_TOKEN`／`GH_TOKEN`、`sk-…`、`ghp_…`、`github_pat_…`、`Authorization: Bearer …` 统一替换为 `<凭证已脱敏>`；凭证只做一次整体替换，避免标记被二次命中产生嵌套；
- 所有进入 HTML 的文本都做 HTML 转义，工单标题里的 `<script>` 不会执行。

## 真实运行渲染

用已有真实运行 `issue-1-1d3bc15b6211` 生成（状态 `published`，含草稿 PR）：

| 检查 | 结果 |
| --- | --- |
| 生成成功 | 是，约 17.6 KB |
| 九个区块齐全 | 是 |
| 显示 PR 链接与获批提交 | 是，PR `#2` 与 `e3ac2677a620a93b844eaae98ab0fa7898efeaed` |
| 显示审核两轮与两条发现 | 是（`changes_requested` → `approved`） |
| 本机路径泄漏 | 未发现（`D:\…`、`C:\Users\…` 均未出现） |
| 凭证泄漏 | 未发现 |
| 离线可用 | 是，Chrome 以 `file://` 打开并截图验证 |

渲染过程中发现并修掉三处真实缺陷：

1. **嵌套 f-string 让脱敏失效**：独立复核表格用了嵌套 f-string，`root` 被当成单元格值，导致脱敏标记没有生成。抽出变量后修复。
2. **列宽被长文本撑坏**：审核表格的「轮次」「发现数」被压成竖排单字，长说明列挤占了宽度。改为固定表格布局并给短列设 `min-width`。
3. **差异行首缩进丢失**：`<pre>` 默认不换行，长行迫使整块横向滚动。改用 `pre-wrap` 折行并保留缩进。

## 现场运行一条新工单

为验证“新任务也能展示”，实际跑了一条本机工单 `demo-test-count-sync-07d7b2a3519d`：目标仓库 README 写“82 项离线测试”、`docs/validation.md` 写“86 项”，而登记检查实测 93 项；任务要求只改这两处文档并复跑检查。

| 项 | 结果 |
| --- | --- |
| 终态 | `awaiting_approval`（停在人工审批，符合预期） |
| 编辑 | 2 次，两个文档各一行 |
| 审核 | 1 轮，`approved`，0 条发现 |
| 独立复核 | `unit` 退出码 0，`Ran 93 tests` |
| 改动正确性 | README 82→93、validation 86→93，与实测一致；未改源码与测试 |
| 花费 | 11 次模型调用、23 次工具调用、¥0.2947（单条工单授权 5 元以内） |

这次运行暴露了两处展示缺陷，已修复：

1. **本地任务没有 Issue，标题只能是 run_id**：报告现在读取可选的 `<run_dir>/meta.json`，支持 `title` 与 `description`，用于本地演示工单；有 Issue 时仍以 Issue 标题为准。
2. **停在人审时没有说明下一步**：新增状态相关的动作提示，例如等待审批时直接给出 `approve <run_id> --commit <sha> --reason "…"`，已发布时说明“草稿 PR 尚未合并”，失败类状态提示 retry 或调整配置。

## 未验证与限制

- 只在两条真实运行上渲染过（一条已发布含 PR、一条停在人审），其余状态（`failed`、`rework_limit_reached`、`review_inconclusive` 等）仅有离线用例覆盖。
- 脱敏是字符串替换，不是通用敏感信息识别系统；新增展示字段时需要重新核对。
- 报告不含实时进度；要看进行中的任务仍需 `repopilot status`。
- 未做录屏；展示材料目前是可复现命令加实际 HTML。
