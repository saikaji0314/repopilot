## 记忆和阶段交接如何理解

本轮没有开启仓库记忆，因而无法判断它的收益或缺陷，也不能声称加向量库就能解决上下文问题。当前仓库记忆是人工确认、有提交和文件指纹的事实书签，跨运行复用；本次缺失的是运行内的工作摘要：已定位内容、已验证假设、修改理由与尚未验证项。二者应分开，过往测试或审批结论不能成为本次通过的依据。

实现、独立复核、审核使用独立阶段上下文，能减少实现方自证，却会丢失调查过程。现在交接需求、差异、检查和发现，缺少紧凑且带来源的调查摘要，可能造成重复检索。应将实现方结论作为待核对数据，审核仍重新取证。当前 diff 摘要上限 4000 字节，而本轮补丁均小于该值，不能把 diff 截断说成本轮已发生的失败原因。

已有逐轮进度提示会列已读位置、编辑文件、检查和剩余额度，但没有保存“为什么读、得到了什么、下一步是什么”。仅再加一句“不要重复调查”缺乏足够依据；更值得先做可定位的搜索和可验证的工作摘要，再进行相同预算下的对照。

## 已完成的确定性修复

增量14发现超限异常跳过沙箱产物导入，清理后已完成编辑丢失，已由 `0568267` 修复。增量15在同一 20 轮历史响应、40 次工具调用下做真实 Docker 重放：旧行为候选 0 字节，修复后保留 2 文件、1073 字节，源仓库均不变。该对照证明产物保存修复，不证明修复正确率提高；重放使用确定性模型，不计入 5 题模型成绩。硬杀、中断与无效产物仍不能承诺全部恢复。

实现／审核分离与审批门禁仍有价值：19487 完整通过，20590 尽管官方测试通过也没有绕过未完成的审核。接下来优先保持实验可归因：多模型配置作为独立产品增量；后续先做搜索范围控制，再做工作摘要与阶段预算，每次只改变一个主要因素，保留原始基线，另建尝试与预先固定的比较协议。
