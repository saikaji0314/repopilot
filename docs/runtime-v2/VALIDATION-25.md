# 增量25：版本化资料与决定管理

日期：2026-10-27。基线：`e5eb154`。目标为M2资料与决定服务的本地机制，对应正文／增量索引、来源和确认状态、角色取资料及旧依据失效；不是模型效果或记忆收益实验。

后续审核发现本文测试未覆盖的三项缺口：发布中断与资料变更的恢复、人工确认事件保留、密集短行检索。597通过是当时的测试结果，不能代替完整需求验收；修复与补充验证见[增量26](VALIDATION-26.md)。

## 做到什么

- 以稳定ID登记项目／任务／决定／证据，正文保留在文件中，历史以内容版本保存；SQLite仅存元数据、关系、状态、章节位置与派生词项。
- 局部改删只更新变化文档的相关块；保留其他文档行和未变化块。同步事务失败可回滚并重试，历史仍可回查。
- 人工确认绑定具体版本，修改后退回提议；显式替代保留去向并继承必需约束，关系目标缺失／失效可查看。
- 准备时固定清单，实现与审核取得相同依据及必需正文；可用`read_material`读取清单内固定版本，片段进入有界工作集并保留来源和版本。
- 结构化`decisions`落为任务范围的提议文档；已保存本地人工答复导出为有来源的确认任务资料，不把实现者理由自动提升为项目规则。
- 来源、候选规则、正文历史或确认状态变化时停止沿用；普通答复不能刷新依据，需显式人工确认和`knowledge refresh`，随后重新检查与审核。
- 资料进入批准摘要，批准和发布前校验版本／正文完整性，任何真实远端动作前拒绝失效依据。原无资料历史运行保持兼容。

用法、取舍和限制见[项目资料协议](KNOWLEDGE.md)。

## 核查证据

| 需求／风险 | 机制证据 |
| --- | --- |
| 改一份资料不重建全局 | [test_knowledge.py](../../tests/runtime/test_knowledge.py)验证仅解析变化文档，另一文档索引行与未变化章节键保留 |
| 删内容不残留当前检索 | 删除文件／段落后检索为空，旧版本仍可读且标历史 |
| 同步中断可恢复 | 模拟一批索引更新中断，所有行回滚，随后同步补齐；人工文档导出后任务检查点丢失也能幂等恢复 |
| 提议不能当确认 | 四类资料均先为提议，默认检索／运行排除；旧版本确认不能确认新正文，机器不能覆盖已确认生成文档 |
| 独立但充分的上下文 | [test_knowledge_integration.py](../../tests/runtime/test_knowledge_integration.py)验证实现／审核同清单，读取固定原文，首轮审核不继承机器决定提议 |
| 旧依据不会因刷新丢失 | 保留完整清单历史，审核行关联清单，决定关联代码现场及资料版本，刷新后仍能回查 |
| 改验收不能自证通过 | 候选改写已登记规则会暂停；普通human answer不能代替资料刷新 |
| 资料失效不能沿用批准 | 原文改变／删除、索引不可用、历史正文缺失均阻断；已批准运行在远端访问前拒绝失效依据 |
| 正常等待／恢复兼容 | M1答复、重复答复、固定SHA批准、返工次数和费用继承均参加回归；刷新不清零，也不修改原任务 |
| 资料过大不偷偷丢约束 | 必需正文超限先暂停；非必需大段可明确省略或保留目录，读取边界不等于完整性校验边界 |

## 限制

这些结果证明本地协议和上述场景，不证明真实模型会正确使用资料或因此提高任务成功率。检索为词项匹配，无embedding或图数据库；没有开始冻结的记忆收益对照。决定完整性依赖结构化报告，未把原始模型思考链当资料。

本增量不含Issue评论往返、三批提问上限、平台身份、任务拆分、并行整合、双视角／AB审核；未运行真实Docker模型任务、SWE-bench、跨机器同步或高并发压力测试。12项跳过不计为通过；未重建发行包。
