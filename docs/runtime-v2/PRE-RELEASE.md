# 预发行验收边界

预发行的目标是让新的使用者能从发行包安装，配置自己的模型和托管平台凭证，在可信仓库中运行小任务并得到可核对的草稿 PR。它不是生产级修复率或无人值守合并承诺。复杂任务的真实效果及失败见[增量18](VALIDATION-18.md)，原始五题开发基线保留。

## 开始打包前

1. 合入并行托管平台接入的稳定提交，确认现有 GitHub 行为及新接口回归通过；GitLab 等平台按离线验证／真实 API 验证分别标注。不能用协议测试代替真实交付。
2. 维护者已选择 MIT，自有代码许可见根目录 [LICENSE](../../LICENSE)；第三方材料保留原许可。构建元数据需声明 MIT 并携带许可文件。
3. 固定发行提交和候选版本，移除占位版本与阻止发行的元数据；选用预发行版本语义，正式兼容性承诺另行说明。实际上传、远端 tag 或 GitHub Release 是候选包验收后的独立发布动作。

## 安装后必须成立

- 模型／平台配置可从操作者指定的环境文件或环境变量读取，不要求修改 site-packages；不把密钥放入 YAML、模型工作区或产物。
- 默认运行目录位于用户可写位置；现有源码 checkout 的 `.local/runtime`、SQLite、预算和 worktree 路径不静默迁移。明确记录选择规则和覆盖选项。
- wheel 包含执行 worker、报告 CSS 和许可；源码包包含对应文档、示例与测试，排除本地交接、真实运行数据、`.env` 和原始模型会话。
- 共享配置规则须覆盖模型、GitHub／GitLab、监听、恢复和报告入口；只读状态、报告、帮助等操作不要求模型凭证。

## 可复核的发行验证

在源码目录之外的新虚拟环境安装 wheel 与完整依赖，检查导入来自安装包。验证 CLI 帮助、配置加载和错误提示、用户数据目录、离线报告及一次确定性任务的持久化恢复／审批边界。Docker 作为可选依赖环境验证，不声称未安装时自动具备隔离能力。

对已支持供应商运行离线协议测试；真实服务未验证的适配器保留明确标记。使用合成凭证运行回归，输出先脱敏再保存，不继承维护者真实凭证作为测试数据。冻结产物摘要、依赖约束和验证日志后，再形成发布说明与安装命令。

发布说明必须包含：适用场景、支持的平台／模型及验证层级、操作步骤、升级与现有运行目录规则、费用估算边界、可信仓库前提，以及仍未解决的长调查、上下文超限和复杂任务修复限制。交付终点继续是人工批准具体提交后的草稿 PR，不增加自动合并或部署。
