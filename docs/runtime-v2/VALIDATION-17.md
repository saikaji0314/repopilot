# 增量17：限定搜索范围与覆盖信息

日期：2026-10-18。来源：[Harness诊断](HARNESS-FINDINGS.md)中 20212 的重复搜索，以及原搜索不支持目录／文件类型范围、只返回笼统截断标记的问题。

## 完成条件与实现

- `search_text(query)`、`list_files()` 的旧用法保持有效；新增 `path / file_glob`，允许指定子目录或单文件、按文件名过滤，不按语言绑定。完整字段与示例见[搜索协议](SEARCH.md)。
- 目录在遍历前选择，文件名在读取前过滤。仍最多读取 2,000 个候选文件、返回 20 处匹配，文件列表最多 200 项；新增两种工具的 20,000 文件名筛选限额，防止模式过滤后无界枚举普通文件。
- 返回实际范围、筛选／读取／跳过数量及 `match_limit / file_limit / entry_limit / result_limit` 停止原因。搜索 `complete` 区分完整零匹配与未覆盖／未读取完；不会把跳过二进制等文件当成全部读过。目录 I/O 错误不再被 os.walk 静默吞掉后误报完整结果。
- 复用读写路径和敏感文件规则，补齐 Windows 带根但无盘符路径的入口拒绝；例如 `/etc` 不再先尝试检查宿主路径是否存在。模式不含目录、盘符或 NUL，不执行 shell 或正则。
- 宿主与容器共用 `execution/files.py`；新参数经固定 RPC 传入容器，在容器内完成筛选。工具描述解释收窄范围和覆盖标记；模型、阶段提示词、记忆、预算及检查机制未改动。

## 效果边界

本增量证明“有范围时工具能找到被旧全仓限额挡住的目标”，尚未证明模型会合理选择范围或减少重复查询。没有新增收费调用，没有重跑／改写增量15的 SWE-bench 成绩。后续真实效果比较应冻结任务、模型与预算，只比较搜索工具这一主要因素，并分别观察查询次数、首次编辑前调用量、超限及官方验收；不能用本轮文件测试代替这个比较。

文件名 glob 不支持目录模式、正则、忽略大小写或续页游标。20,000 上限约束纳入筛选处理的可访问文件数；os.walk 仍会枚举当前目录，目录层级不计数，不能把它当成目录元数据访问的硬限额。记忆、工作摘要与阶段预算仍为后续独立增量，避免同一实验中同时改变多个因素。
