# 限定范围的仓库搜索

`search_text` 和 `list_files` 接收两个可选参数，旧调用保持有效：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `path` | `.` | 仓库根目录内的目录或单文件；目录递归遍历 |
| `file_glob` | `*` | 仅匹配文件名，支持 `*`、`?`、`[...]`，例如 `*.py`、`test_*.ts` |

模式不包含目录分隔符；需要选择目录时使用 `path`，不接受 `src/*.py` 或 `**/*.py` 这类混合模式。字面查询与文件名模式在 Windows、Linux 上均区分大小写。它们不调用 shell，也不执行正则表达式。所有结果路径始终相对仓库根，可以直接用于 `read_file`，不会因为选择子目录而改变基准。

```json
{"query": "normalize", "path": "src", "file_glob": "*.ts"}
```

以上是 `search_text` 的参数；`list_files` 可先用 `{"path":"src","file_glob":"*.ts"}` 查找文件。已知具体文件时可直接指定 `path="src/main.ts"`。

## 限额与结果解释

目录选择在遍历之前生效，文件名过滤在读取文件之前生效。搜索最多尝试读取 2,000 个符合模式的文件、返回 20 处匹配；每处仍是原来的行号和最多 200 字符片段。单文件大小、UTF-8、敏感文件与链接规则保持不变。两种工具每次最多纳入筛选处理 20,000 个可访问文件名，文件列表最多返回 200 项。此限额不计目录层级，os.walk 仍会枚举当前目录，不是目录元数据访问的硬限额。

搜索结果保留 `matches / skipped_files / truncated`，并补充：

| 字段 | 解释 |
| --- | --- |
| `path / file_glob` | 本次有效范围；目录名规范为 `/` 分隔 |
| `visited_files` | 已纳入文件名筛选的可访问文件数；可能含探测读取／列表上限所需的下一项 |
| `scanned_files` | 已尝试读取的匹配模式文件数，包含读取失败的文件 |
| `skipped_files` | 二进制、过大、非 UTF-8 或 I/O 问题导致未读的文件数 |
| `truncation_reason` | 正常结束为 null；提前停止为下表中的原因 |
| `complete` | 未因限额停止且没有跳过文件时为 true；只表示本次范围已搜索，不代表全仓覆盖 |

文件列表返回 `files / path / file_glob / visited_files / truncated / truncation_reason`，不会读取文件内容。

| 停止原因 | 下一步 |
| --- | --- |
| `match_limit` | 匹配已达 20，收窄目录、文件类型或查询；不推断总共只有 20 项 |
| `file_limit` | 已尝试读取 2,000 个符合模式的文件，收窄目录或文件类型 |
| `entry_limit` | 已处理 20,000 个可访问文件名，优先缩小目录 |
| `result_limit` | 文件列表超过 200 项，缩小目录或文件名模式 |

命中 20 项即停止，可能刚好只有 20 项；`truncated=true` 表示未继续穷尽该范围，不断言后面一定还有匹配。不提供续页游标；本增量优先引导缩小搜索范围。`complete=false` 的零匹配不能作为“不存在”的结论，即使 `truncated=false` 也要看是否存在跳过文件。目录遍历出现权限／I/O 错误时返回 `repository_io_error`，不会将它伪装成完整的空结果。

## 执行与验证边界

范围选择仍经过读写共用的路径检查，拒绝上溯、盘符、绝对／带根路径、敏感路径和符号链接。通配符不能绕过敏感文件过滤；公开 `.env.example` 仍允许访问。

本机与 Docker 共用 `execution/files.py` 的实现；范围参数通过固定 JSON RPC 传递，在容器内筛选和读取，不在宿主执行搜索。未增加运行时依赖或更改镜像。工具说明加入收窄范围和覆盖信息的用法；没有同时修改阶段提示词、记忆、预算或模型参数。

基于 5 题开发基线发现的问题与待测方案见[Harness诊断](HARNESS-FINDINGS.md)，本增量验证见[增量17](../VALIDATION.md#历史机制验收)。确定性文件案例和容器一致性证明工具能力，不证明模型会主动使用范围参数，亦不代表 SWE-bench 成功率已经提高。
