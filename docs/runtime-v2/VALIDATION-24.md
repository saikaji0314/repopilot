# 增量24：统一本地人工请求与恢复基础

日期：2026-10-27。代码基线：`8757c1b`。范围为M1本地机制，不包含真实模型、平台评论、任务拆分、并行双审或外部交付验证。

## 实现的行为

- 工作区任务的实现／返工需求不足，或审核无法判断且提出问题时，持久化为`needs_input`，保留部分改动与累计用量。
- 新增`human list`和`human answer`，显式指定请求ID与版本；答案保存后为`paused`，后续`resume`才调用模型。
- 请求绑定运行、任务、原Issue、业务答案版本、阶段、基线、当前提交、工作区摘要和批准依据；过期或串任务的答复被拒绝，相同答复重复提交无额外效果。
- 需求答案进入实现／审核上下文及批准摘要；旧结果失效，审核阶段的问答先重新独立检查，返工暂停后恢复不重复计数。
- 固定提交批准、拒绝和中断现场恢复写入同一请求协议，但仍使用专门命令和原校验，普通答案不能授予这些权限。
- 请求与任务状态共用现有SQLite行更新；历史无补充答案的批准摘要兼容，显式retry继承已确认答案和原运行来源。
- CLI和报告展示请求／答复，模型来源文本脱敏，HTML中问题与答案转义。

接口、状态及限制见[人工协作协议](HUMAN.md)。

## 验证方法与结果

使用确定性模型消息、真实本地Git、SQLite和独立CLI子进程，不调用付费API。重点覆盖实现中等待／重启、审核中补充、返工中暂停、重复与冲突答复、版本过期、跨运行误用、旧批准兼容、现场恢复、费用继承和报告转义。

本次环境：Windows，Python 3.12.4，SQLite 3.45.3；未增加项目依赖。

| 检查 | 结果与说明 |
| --- | --- |
| 首轮相关旧测试 | 43通过／3失败；调整了新审核等待的预期，保留显式no-workspace只读报告兼容，之后继续验证 |
